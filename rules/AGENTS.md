# 苍蓝协奏台（external-orchestrator）主动协作与省 Token 铁律

你拥有 `external-orchestrator` MCP 工具。**核心目标：多用外部模型协作，最大限度节省主规划手（你）的 Token 消耗与上下文窗口。**
你只负责**轻量思考规划 + 派单指令 + 最终抽查验收**，把消耗大量 Token 的文件阅读、代码编写、文本生成、命令排查全部优先交给苍蓝协奏台中的外部高性价比模型执行，**严禁等用户点名才使用**。

- **高频主动派单场景（凡预计消耗较多输入/输出 Token 的工作，一律优先派单）**：
  - **读文件 / 调研代码 / 搜目录**：需要翻阅多个文件、长文件或排错定位时，不要主脑自己大段读入上下文 → 直接用 `worker_execute(mode: "readonly", profile: "coder")` 让外部模型去读并只给主脑返回精简结论。
  - **写代码 / 改文件 / 重构 / 写脚本 / 改配置或 MOD**：凡涉及 >15 行代码编写、多处修改、样板生成、补测试 → 直接用 `worker_execute(mode: "edit" 或 "full", profile: "coder")` 派单执行。
  - **跑命令 / 测构建 / 查长日志**：需要执行测试或分析长输出时 → 用 `worker_execute(mode: "full")` 让外部模型消化长日志并返回摘要。
  - **长文本起草 / 总结 / 翻译 / 格式批量转换** → 直接用 `worker_generate(profile: "fast" 或 "default")`。
- **主脑直做边界（仅限极轻量或高危操作）**：
  - 简短闲聊问答、单处三五行以内的极小微调，或删库/改系统级关键配置/公开发布等不可逆高风险操作，才由主脑直接处理。
- **首次派单自检与静默降级**：
  - 会话首次派单前调用 `worker_list_models` 确认已启用渠道；若当前设备尚未配置任何可用渠道，静默降级由主脑自行完成，不报错、不打断（仅在用户主动询问外部模型配置或要打开面板时才输出 `[苍蓝协奏台](sidecar://external-orchestrator/console/)`，避免 Antigravity 2.35.1+ 自动弹开侧栏打扰）。
- **轻量验收**：`worker_execute` 返回后，主脑根据其 `modifiedFiles` / `createdFiles` 和 `summary` 做最小化抽查验证，确认无误即可汇报，避免重复全文读取浪费 Token。
